## 快速开始

```bash
cd webui
npm install
npm run dev        # → http://127.0.0.1:5273（开发用；/api、/media 代理到本机服务进程）
npm run build      # tsc -b && vite build（产物进仓库根 dist/web，由 npm start 托管）
npm run typecheck  # 只做类型检查
```

### 与后端的关系（已接线）

本前端**只经本机服务进程的 HTTP 接口取数**（HLD §1），不再有演示数据模式
（`fixtures.ts` / `mock.ts` 已按 `REQ-019` / `AC-010` 删除）：

| 场景 | 怎么跑 | 说明 |
| --- | --- | --- |
| 完整功能（推荐） | 仓库根 `npm run build` → `npm start` | 服务进程托管 `dist/web` 并打开**带启动令牌**的页面（同源）；读写全部可用 |
| 纯界面开发 | `cd webui && npm run dev` | 5273 dev server 代理 `/api`；读操作可用（受 Origin 守卫，写操作请用上面的完整流程） |

服务进程端口默认读应用数据目录 `config.json` 的 `server.port`（0 = 自动）；
开发期代理目标默认 `http://127.0.0.1:8787`（可用 `MESSAGEPICK_SERVER_PORT` 覆盖），
请把开发用 `server.port` 固定为 8787（与根 `vite.config.ts` 同口径）。

> 令牌口径（详设 §4.1）：服务进程打开页面时经 URL fragment（`#token=...`）注入启动令牌，
> 页面只在内存持有、用后从地址栏抹去；写请求携带 `x-messagepick-token` 头。无令牌时页面为只读。

## 代码结构

```
src/
├── types.ts                  ★ 契约层映射（含错误标识与统一呈现口径）
├── api/
│   ├── index.ts              ★ 34 条 API 的唯一调用点（组件只依赖它）
│   ├── client.ts               传输层：本机服务 HTTP + 启动令牌 + 信封归一
│   └── map.ts                  适配层：契约线格式 ↔ 界面视图模型（含展示名缓存）
├── state/appState.tsx        全局筛选条件 · 更新状态 · 抽屉互斥 · 设置面板
├── components/
│   ├── shell/                外壳：AppShell / GlobalFilterBar / FirstRunGuide / SettingsDialog
│   ├── ui/                   基础展示单元（含异常与空态的统一呈现）
│   ├── charts/               ECharts 按需懒加载容器 + 各图表
│   └── unit/                 业务展示单元：梗单元 / 消息详情 / 生成面板 / 社交各面板
└── pages/                    总览 / 梗分析 / 信息提取 / 社交画像
```

### 几处与契约直接对应的实现要点

- **全局筛选条是唯一筛选控件**（`REQ-004`、`REQ-049`）：只有 `shell/GlobalFilterBar` 产生
  群多选 · 时间范围 · 关键词 · 身份；三个模块只消费，不自建同类控件。关键词的匹配对象
  随模块变化（`REQ-005`），在控件上直接标注。
- **身份无需手工设置**（`REQ-006`）：界面只展示「我」并据此提供「我相关」视角，没有输入框。
- **异常统一呈现**（`REQ-016`）：`types.ts` 的 `ERROR_PRESENTATION` 把 16 个错误标识映射到
  五种处置方式（重试 / 清除筛选 / 引导更新 / 返回 / 确认），三模块与外壳共用 `ErrorState`。
- **图表按需加载**：`REQ-010` 要求万条级首屏 < 2s，故 ECharts 与 `echarts-wordcloud`
  都在首次绘制时动态引入（首屏 JS 因此从 473KB 降到约 122KB gzip）。
- **术语口径**（`REQ-017`）：统一用「梗单元」；模块一「梗词云」与模块三「个人标签词云」
  区分命名；「梗生命周期」与「消息时间轴」不共用名称。

**分析依赖模型服务且按需触发**：在筛选条选中群后点「分析」即对所选群执行梗分析 + 信息提取（未选群 = 全部群）；
采集后的自动分析默认关闭（设置里可开启「采集完成后自动分析全部群」）；社交画像在进入社交页时按需构建（跨群口径）。
模型服务未配置时（设置 → 模型服务：地址 / 模型名 / 密钥三项缺一不可）采集仍成功，但分析任务会失败（错误可查 —— `REQ-016`）。
