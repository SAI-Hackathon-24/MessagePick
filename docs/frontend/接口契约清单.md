# 接口契约清单（v0.1 · 可扩展草案）

> **目的**：`raw_design.md` / PRD 未完成期间，先把「前端需要什么数据」这件事固定下来，
> 让 core / utils 并行开发时不至于返工。**本文只是契约草案，不是最终协议。**
>
> **三个层次的约定**：
> 1. **底层数据**：来自 `wechat-cli` 的真实 JSON（已核对源码，见下）。
> 2. **中间层**：本文件定义的领域对象（`src/types.ts`）。
> 3. **扩展层**：所有对象都带 `ext?: Record<string, unknown>`，后端新增字段不会让前端报错。

---

## 1. 已完成核对的底层接口（wechat-cli 源码级）

来源仓库：`SAI-Hackathon-24/wechat-cli`（commit `dbdb4d6`，含 Linux 媒体解密扩展）。
以下 JSON 结构均从源码 `wechat_cli/commands/*.py` 与 `core/messages.py` 实际读出，非猜测。

### 1.1 `wechat-cli sessions --limit N`

```jsonc
[
  {
    "chat": "24组·聊斋开发群",     // 展示名
    "username": "38912345678@chatroom",
    "is_group": true,              // '@chatroom' in username
    "unread": 12,
    "last_message": "那我把词云那块先搭出来",
    "msg_type": "文本",             // format_msg_type 后的中文名
    "sender": "陈禹哲",             // 群聊时为本条消息发送者
    "timestamp": 1780000000,       // 秒
    "time": "06-09 21:30"          // '%m-%d %H:%M'
  }
]
```

### 1.2 `wechat-cli history "群名" --limit N --offset M [--type T] [--media] [--start-time] [--end-time]`

```jsonc
{
  "chat": "24组·聊斋开发群",
  "username": "38912345678@chatroom",
  "is_group": true,
  "count": 50,
  "offset": 0,
  "limit": 50,
  "start_time": null,
  "end_time": null,
  "type": null,
  "messages": [
    "[2026-06-09 21:30] 陈禹哲: 那我把词云那块先搭出来"
    // ⚠️ 目前是「已格式化的行文本」，不是结构化对象
  ],
  "failures": null
}
```

> **前端适配说明（重要）**：`messages` 当前为字符串数组，前端要展示结构化会话流需要解析。
> 已在 `src/types.ts` 定义 `NormalizedMessage`，并保留 `raw_line` 作为保底字段：
> adapter 未升级时至少能按原文显示，**不会阻塞 UI**。
> 建议 core 侧直接提供结构化版本（字段见下表），可省掉一层易碎的正则解析。

**建议的结构化消息字段**（`NormalizedMessage`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 建议由 `local_id` 派生，用于「跳转原消息」 |
| `chat` / `username` | string | 会话标识 |
| `sender` / `sender_username` | string | 发送者显示名 / wxid（可由 `Name2Id` 还原） |
| `is_self` | boolean | 是否本人发送 |
| `type` | `text\|image\|voice\|video\|sticker\|location\|link\|file\|call\|system` | 对应 `MSG_TYPE_FILTERS` |
| `text` | string | 已剥离类型标签的展示文本 |
| `raw_line` | string | 原始行，保底显示 |
| `timestamp` / `time` | number / string | 秒级时间戳 / 格式化时间 |
| `media_path` / `media_exists` | string / boolean | `--media` 解出的本地路径与文件存在性 |
| `voice_duration` | number | 语音时长（秒）**待 core 确认能否取到** |
| `width` / `height` | number | 图片/表情尺寸，用于瀑布流占位（V2 图片可从容器解析宽高） |

### 1.3 `wechat-cli stats "群名"`

```jsonc
  "is_group": true,
```

### 1.4 `wechat-cli members "群名"`

```jsonc
  "group": "24组·聊斋开发群",
  "username": "...",
  "member_count": 12,
  "owner": "陈禹哲",
  "members": [ { "display_name": "陈禹哲", "username": "wxid_xxx", "remark": "组长" } ]

```

### 1.5 其余命令

| 命令 | 关键返回 | 前端用途 |
|---|---|---|
| `contacts --query/--detail` | 昵称、备注、微信号、签名、头像 URL、账号类型 | 头像、联系人解析 |
| `search "关键词" --chat X --type T` | 与 history 同构（分页信封） | 关键词搜索 |
| `unread` | 未读会话列表 | 总览角标 |
| `new-messages` | 上次以来的增量消息，状态存 `~/.wechat-cli/last_check.json` | 增量分析（可做「有新消息」提示） |
| `favorites --type/--query` | text/image/article/card/video | 收藏（暂未在 UI 中使用） |
| `export --format markdown\|txt` | 导出文本 | 报告导出（待定） |
| `media "群名" --type image\|sticker --out` | 解密产物写入 `state/decoded/` | 梗卡片的表情包素材、通知图片 |

## 2. 前端需要的中间层接口（**待 core 实现**）

统一响应信封（`ApiEnvelope<T>`）：

```ts
{ ok: boolean; data: T; source?: 'mock'|'wechat-cli'|'llm'|'mcp'|'cache';
  elapsed_ms?: number; notice?: string; error?: ApiError; ext?: Record<string, unknown> }
```

错误码已是**闭集**，前端按码渲染不同引导：

```ts
'NOT_INITIALIZED' | 'CHAT_NOT_FOUND' | 'NO_MESSAGES' | 'LLM_TIMEOUT'
| 'LLM_FAILED' | 'MEDIA_MISSING' | 'PERMISSION_DENIED' | 'UNKNOWN'
```

### 2.1 建议路由表

| 方法 | 路由 | 对应能力 | 返回类型 | 复用现有命令 |
|---|---|---|---|---|
| GET | `/api/sessions` | 会话/群列表 | `ChatSession[]` | `sessions` |
| GET | `/api/chats/:chat/members` | 群成员 | `ChatMember[]` | `members` |
| GET | `/api/chats/:chat/messages` | 原始消息 | `Paginated<NormalizedMessage>` | `history` |
| GET | `/api/chats/:chat/stats` | 统计 | `OverviewStats` 子集 | `stats` |
| GET | `/api/chats/:chat/media` | 媒体清单 | 媒体路径 + 存在性 | `media` |
| GET | `/api/overview?chats=&start=&end=` | 总览聚合 | `OverviewStats` | `stats` × N + core 聚合 |
| POST | `/api/analyze/memes` | **梗提炼** | `WordCloudItem[]` + `MemeCard[]` | core + LLM |
| POST | `/api/analyze/notices` | **通知提取** | `NoticeItem[]` | core + LLM |
| POST | `/api/analyze/profiles` | **画像与匹配** | `PersonalityProfile[]` / `MatchResult[]` | core + LLM |
| POST | `/api/remix` | **梗再创作** | `MemeRemixJob` | LLM 出图 |
| PATCH | `/api/notices/:id` | 状态/提醒 | `{ id, status }` | core 持久化 |
| GET | `/api/analyze/progress/:jobId` | 进度（可选） | `AnalyzeProgress` | SSE / 轮询 |

请求体统一为 `AnalyzeRequest`：

```ts
{ chats: string[]; start?: string; end?: string; force?: boolean }
```

### 2.2 领域对象字段清单

完整定义见 `src/types.ts`（每个字段都有注释）。核心必填项：

| 对象 | 必填字段 | 说明 |
|---|---|---|
| `MemeCard` | `id, term, count, meaning, category, chats, first_seen, last_seen, lifespan_days, trend[], timeline[], top_contributors[], samples[]` | 前 8 项支撑目标.md 对梗卡片的全部要求 |
| `NoticeItem` | `id, headline, summary, chat, category, priority, status, timestamp, sources[], entities, tags[]` | `headline` = AI 一句话总结；`sources` = 所有群消息来源 |
| `PersonalityProfile` | `id, name, persona_tags[], one_liner, dimensions[], style_keywords[], catchphrases[], stats` | **待定稿** |
| `MatchResult` | `id, a, b, score, reasons[], icebreakers[], shared_topics[]` | **待定稿** |

### 2.3 扩展点（新增字段的正确姿势）

| 场景 | 做法 | 前端是否需要改 |
|---|---|---|
| core 多返回一个字段 | 放进该对象的 `ext`，或直接在类型里加可选字段 | **不需要**，UI 自动忽略未知字段 |
| 新增一种再生成形态 | 往 `RemixKind` 加枚举 + `REMIX_KIND_LABEL` 加中文名 | 不需要，按钮自动出现 |
| 新增一种通知类型 | 往 `NoticeCategory` 加枚举 + 标签映射 | 不需要，筛选 Chip 自动出现 |
| 新增一个画像维度 | 往 `dimensions[]` 里加一项 | 不需要，雷达图自动扩轴 |
| 新增一个页面 | 在 `AppShell` 的 `NAV` 加一项 + `App.tsx` 加路由 | 只改配置，不碰布局 |
| 接入真实后端 | 改 `src/api/index.ts` 里各方法的实现为 fetch | **不需要**，组件零改动 |

## 3. 接入真实数据的切换步骤

```ts
// src/api/index.ts —— 现在是：
listMemes: (chats, sort) => wrap(() => mockMemes(chats, sort)),

// 切换为真实后端只需：
listMemes: (chats, sort) =>
  fetch(`/api/analyze/memes?chats=${chats.join(',')}&sort=${sort}`).then((r) => r.json()),
```

同时把 `vite.config.ts` 里预留的 proxy 打开：

```ts
proxy: { '/api': { target: 'http://127.0.0.1:8765', changeOrigin: true } }
```

> 提示：`source` 字段建议由后端如实填写（`wechat-cli` / `llm` / `cache`），
> 前端已经用它渲染「数据来源」提示，方便路演时说明链路。
