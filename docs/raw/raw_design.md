# MessagePick 原始设计

## 1. 目标

实现一个 webui 的微信群聊分析软件。实现三大核心功能：

1. **群聊梗分析**——这个群在玩什么，有什么共同记忆？
2. **群聊信息提取**——群里发生了什么？
3. **正向 / 反向社交**——我要不要参与、怎么参与？

三模块都做，实现上**没有严格先后顺序**；§3 内出现的排序表述仅为**建议顺序**，不构成依赖约束。

数据源为真实微信消息（经 `wechat-cli` 采集），**不做演示数据版本**。

---

## 2. 全局约定（三模块通用）

### 2.1 术语

| 术语 | 含义 |
| --- | --- |
| **梗** | 群内被反复复用、有特定含义或固定用法的表达单元。形态包括文字口头禅、缩写、内部称呼、句式模板、梗图 / 表情包、事件代称。不引入英文术语。 |
| **梗单元** | 梗的最小展示与操作单元（解读 + 信息 + 来源 + 生成动作）。即原稿中的「梗卡片」。 |
| **梗王** | 使用该梗次数最多的群成员，用于回答「这梗是谁带起来的」。只统计「说了多少次」这类可统计事实。（性格标签是模块三的独立功能，需本人确认，见 §5.7，不属本口径） |
| **梗生命周期** | 首现 → 爆发 → 衰减 → 沉寂。这是梗分析的核心叙事。 |
| **消息时间轴** | 模块二里把全部群消息按时间排列的视图。与模块一的「梗生命周期」是两个不同视图，不共用名称。 |
| **词云** | 两个不同物，勿混：模块一的词云 = **梗词云**（字号 = 梗的出现频率）；模块三的词云 = **个人标签词云**（按某成员自己的 tag 生成）。 |

### 2.2 全局筛选（作用于三个模块的所有视图）

一行筛选区，统一控制：**群多选 · 时间范围 · 关键词 · 当前用户身份**，并始终显示「记录更新至 X」，避免用户误以为已覆盖全部实时消息。

- 「当前用户身份」维度只在**模块一（梗分析）与模块三（社交）**生效；模块二不区分身份。
- 模块二原本自带的「按时间筛选 / 按关键词筛选」「选中一个或多个群」即本筛选条的时间、关键词、群多选三个维度，**不另做一套**。

### 2.3 非功能需求

- **可追溯**：每个结论都能回到原始消息（首现、最近、每条精华消息、梗王统计均带来源）。
- **可纠正**：用户能改判 AI 的分类与标注（不是梗 / 不感兴趣 / 梗王有误），改判立即影响后续结果。
- **可确认**：新梗候选、素材使用、对外分享均需用户确认后才生效。
- **隐私**：聊天记录按授权范围处理；支持删除原始记录及其派生结果；云端分析需明确告知数据去向。
- **性能**：三个模块统一为**万条级消息首屏渲染 < 2s**（CHG-013 裁定）。

  > 遗留风险：模块三的匹配范围是跨全部已采集历史群，真实量级可能大于「万条级」。若实测超限，需回流改此指标。

### 2.4 合规底线

- 生成内容明确标注为「创作」，不伪造成真实聊天记录；
- 改编热门表情包需注意原作者的版权与使用许可；
- 用成员头像、照片、原话作素材，必须经本人或用户确认；
- 「创造新梗」只产出候选，不自动发布，也不自动替换群内正在用的说法。

### 2.5 数据源

- 微信消息：`wechat-cli`（群消息、群成员身份）。
- 通讯录 / 好友列表：用于**跨群身份对齐**，作为候选匹配的来源之一；最终映射须经人工确认（见 §5.1）。

## 3. 模块一：群聊梗分析

### 3.1 定位

把群聊里反复出现的「梗」沉淀成**可浏览、可追溯、可再创作**的群文化资产。

一句话价值：让潜水的人三分钟看懂「这个群在笑什么」，让老群友能翻回某个梗的第一次出现，让想用的人立刻拿到一张能发的图。

### 3.2 目标用户与场景

| 用户 | 场景 | 期望 |
| --- | --- | --- |
| 新入群 / 长期潜水的人 | 大家突然开始刷同一句话、同一张图 | 快速补课：什么意思、怎么来的、现在怎么用 |
| 想接话的人 | 想参与但怕用错、怕过时 | 知道这个梗现在还能不能用、怎么用 |
| 群主 / 管理员 | 想做年终总结、新人手册 | 复盘群文化，知道每个梗是谁带火的 |
| 内容创作者 | 想把群梗做成表情包 | 一键生成能直接发的图和新说法 |

### 3.3 功能需求

筛选条见 §2.2。F1–F5、G1–G4 为本模块功能编号。

#### F1 词云视图

- **字号 = 该梗的出现频率**。口径可切换：**累计出现次数（默认）** / 指定时间窗内的出现频次。
- 颜色 = 梗类型（口头禅 / 内部梗 / 表情包梗，≤3 类并带图例）。

#### F2 点击即展开

点击任意词 → 从该词位置展开对应的**梗单元**。

#### F3 布局切换

- **按热度**：字号映射出现频率，聚合成云。
- **按首次出现时间**：按时间先后重排，每个词下标注首现日期（词云版时间轴）。

#### F4 悬停

显示出现次数、首现时间、最近调用、类型。

#### F5 无障碍

提供列表 / 表格视图作为等价形式；类型同时有文字标签，不依赖颜色单独区分。

### 3.4 梗单元（原「梗卡片」）

| 区块 | 内容 | 说明 |
| --- | --- | --- |
| 头部 | 梗名 · 类型标签 · 热度状态（活跃 / 衰减中 / 已沉寂） | 状态由最近调用时间推算 |
| **梗的解读** | 这个梗是什么意思、从哪来、现在怎么用 | 一句话讲清，直接解决「看不懂」 |
| 关键时间 | **首次出现时间**（含来源群）、**最近一次调用时间**（含距今） | 均可点击跳回原始消息 |
| 数量 | 累计出现次数 + 近期趋势 | 趋势为环比，不是绝对值 |
| 时间分布图 | 按月的出现次数柱状图 | 可切换表格；悬停显示数值；标注不完整月份 |
| 生命周期条 | 首现 → 峰值 → 最近，标注活跃天数 | 直观看「火过多久、凉了多久」 |
| **谁在用** | 使用最多的成员标记为**梗王**（附使用次数与占比），并可列出主要使用者 | 只呈现「说了多少次」这类可统计事实，不做性格判断 |
| 精华群消息 | 3 条代表性消息，**文字消息与梗图（图片 / 表情包）都支持**，图片可预览 | 支持展开更多；每条可查看上下文 |
| 相关变体 | 衍生说法（如「下次一定」→「下辈子一定」） | 可点击切换 |
| 再生成 | **单元左下角固定「生成」按钮** | 见 §3.6 |
| 纠正 | 「这不是梗」「不感兴趣」「合并到其他梗」「梗王标注有误」 | 用户可改判 AI 结果 |

### 3.5 梗生命周期视图（时间轴）

- 每个梗一行，横轴为时间，**条带长度 = 生命周期跨度**；条带内按月显示出现强度（顺序色阶）。
- 标出**首现点、峰值、沉寂点**：一个梗从初次使用到无人问津经过了多久，一眼可见。
- **同一时间段在频繁用哪些梗**：按月份聚合，展示当月领跑梗。
- 点击行或单元格 → 打开对应梗单元。
- 提供表格视图（等价数据，可复制）。

### 3.6 梗的再生成

入口：梗单元**左下角「生成」按钮**，展开生成面板。

- **G1 生成表情包**：选模板 + 编辑文案 → 生成 4 张 → 复制 / 下载。
  素材来源分三档，用户可选：
  1. **参考群内相关图片**：用本群出现过的梗图作为参考或底图，生成风格一致的图；
  2. **改编热门表情包**：套用当前流传的模板与句式（需注意版权）；
  3. **纯模板生成**：系统内置模板，不依赖任何外部素材。
- **G2 生成更多文字变体**：基于该梗的用法，生成更多说法 / 句式（默认 5 条，可一键复制），用来接话或发朋友圈。
- **G3 根据聊天内容创造新的梗**：从近期聊天中发现**潜在新梗**——反复出现的新表达、群内专有代称、某次事件的说法——生成候选梗单元（含义推测、出处消息、使用示例），**经用户确认后才入库**。
- **G4 规划中**：接话草稿、群年度报告、新人补课卡片、梗百科词条。

### 3.7 本模块本期不做

- 梗的情感倾向 / 立场分析（证据不足，易误判）
- 跨群梗的自动合并（先由用户手动合并）
- 自动判定「梗王」之外的**成员画像**（本禁令仅限模块一；模块三的「人物兴趣画像」不在此列）

真实微信消息接入**不在**「不做」清单内——三模块都接真实数据（见 §1）。

### 3.8 验收路径（演示脚本）

1. 打开词云 → 字号差异明显，图例可辨类型，点击任意词能展开单元
2. 点击「下次一定」→ 单元显示**解读**、首现时间、最近调用、按月分布、**名场面（含梗图）**、**梗王是谁**
3. 切换「按首次出现时间」→ 词云重排为时间序，每个词带首现日期
4. 切到梗生命周期视图 → 生命周期条带可辨，已沉寂的梗一眼看得出
5. 点单元**左下角「生成」**→ 得到 4 张表情包 + 5 条文字变体，可复制 / 下载
6. 点「创造新梗」→ 得到 1–2 个候选梗单元，确认后才进入词云

## 4. 模块二：群聊信息提取

### 4.1 功能逻辑

帮助用户提取并分析聊天记录，方便用户快速获取聊天内容和通知信息。系统自动识别微信消息，以及群公告、@所有人、接龙、投票、报名、缴费、会议、活动、截止日期等，并提取时间、地点、人物、事项、DDL等关键要素。随后，系统依照时间、主题等不同维度进行归档，对于通知按照来源、类型、优先级、待办收集信息并集中展示，形成清晰的通知总览。

### 4.2 用户操作流程

在整理出群消息以后，用户可以按照下面的方式获取：

1. **筛选功能**：可以按照时间筛选 / 用户指定关键词筛选——即 §2.2 全局筛选条，不另做一套。
2. **排序功能**：AI 按照时间排序，用**消息时间轴**排列所有群聊的所有总结出来的消息；也可以选中一个或多个群（全局筛选条的群多选），对其中的消息按时间排序，同样用消息时间轴。
3. **点进一个消息**：用户需要看到的界面包括——heading：AI 一句话总结 + 来自哪个群 + 什么时间；正文：AI 总结 + 所有群消息来源。

### 4.3 实现效果

把碎片化信息变成清晰、可执行、可追踪的清单，避免遗漏重要信息，减少“爬楼”成本，提升群聊协作效率。让用户从繁杂消息中解放出来，真正做到重要通知一眼可见、一键可管、到期不忘。

## 5. 模块三：正向社交与反向社交

核心是一份「人 ↔ 兴趣」的双向索引，**正向**和**反向**只是同一份数据的两个查询方向，不是两套独立逻辑：

- **正向社交**：人 → 兴趣。给定一个人，认识他的爱好，形成"人物兴趣画像"。
- **反向社交**：兴趣 → 人。给定一个爱好，找到有同样爱好的人，即"找搭子"。

分析对象是整个群的社交生态（群整体视角），但匹配范围是跨群的（全部已采集的历史群）。

### 5.1 定位与边界

- 用户**主动查询**（输入条件 → 得到结果），不做自动监测推送。
- AI **只分析、只给建议，不执行任何动作**（不替你发消息、不替你拉群）。
- 纯个人工具，推断结果**不外露**给群成员。
- 建议实现顺序：三大功能中排第三，先做群聊梗分析和群聊信息提取（**仅为建议顺序**，实现上无严格先后依赖）。
- **跨群身份对齐（CHG-013 裁定）**：`wechat-cli` 只能提供群昵称 / 群名片，**没有跨群稳定标识**。因此跨群匹配依赖**人工确认的映射表**——系统给出候选（结合通讯录 / 好友列表），由用户确认「A 群的张三 = B 群的小张」；**未确认的映射不生效**，相关人在未确认前按各自独立个体处理。确认入口的具体形态留待 PRD / 模块阶段决定。

### 5.2 数据模型

三张核心表（或等价的图结构）：

1. **人物（person）**：群成员身份。
2. **兴趣（interest）**：**一级固定五类**——运动 / 艺术 / 游戏 / 娱乐 / 社交；**二级为自由标签**（如「运动」下的乒乓球、羽毛球，「游戏」下的具体端游 / 手游名），二级无预设词表。
   - 原口径「自由标签，无预设分类体系」作废（CHG-012）：改为**一级固定、二级自由**。
   - 雷达图按**一级五类**出维度；点击任一维度才展开该维度下的二级具体词条。
3. **证据（evidence）**：每条兴趣标签都必须能追溯到具体的群消息，用于"打开更多"查看原文。

兴趣标注流程：

- 由 LLM 从群聊消息中**自动抽取**，每条标签必须附带证据消息；抽取时同时判定它属于哪个一级维度。
- 抽取后**自动合并同义二级标签**（例如"羽毛球 / 打羽球 / 约球"归一为同一标签）。
- 支持**人工介入**：增、删、改标签（用户可纠正 LLM 的错误或补充遗漏）。
- 「**社交**」维度的分数**源自群里的发言活跃度**（该量同时也用于 §5.3 的契合度因子；两者用途不同、不叠加）。

### 5.3 契合度计算

人-人配对的「**契合度**」由以下因素构成（本指标原称「匹配度」，CHG-012 改名，口径未变）：

- 共同兴趣标签的**数量**
- 标签的**强度 / 置信度加权**（被多次提到的兴趣权重更高）
- 两人在群里的**实际互动**（互相回复、@、接话）
- 发言量 / 活跃度（**与 §5.2 的「社交」维度分数共用同一份数据，但不重复计入**）

**维度差值**：除契合度总分外，还要逐维度给出**两人的差别**（雷达图叠加对比），使判断更理性、可量化。

**不做时效衰减**：所有兴趣等权，不因时间久远而降权。

**时间轴只做可视化**：§5.5 的时间轴 / 事件流仅用于回放兴衰过程，**不参与**契合度权重计算（CHG-013 裁定）。

### 5.4 产物（四类，均需实现）

1. **兴趣 → 人列表**：每个兴趣下有哪些人。
2. **人 → 兴趣列表**：某人的爱好画像（性格标签须已由本人确认，见 §5.7）。
3. **人-人配对**：两人的共同爱好 + **契合度** + **逐维度差值**。
4. **组局建议**：仅输出**文字建议**，例如"可以约 A、B、C 打羽毛球"，不生成待办、不生成可直接发送的文案。

**反向社交（通过 tag 搜人）**，采用搭子社交形式，支持两个检索入口：

- **按维度搜**：搜某个一级维度分数高的人（如「运动维度分高的人」）。
- **按具体 tag 搜**：搜某个二级标签（如「乒乓球」）。
- 结果中展示每人的**回复时长**与**活跃度**（口径见 §5.6）。

### 5.5 前端展示（七种形态）

| 形态 | 职责 |
| --- | --- |
| 时间轴 / 事件流 | 兴趣也有首次出现时间和兴衰过程，可回放 |
| 评分卡 / 仪表盘 | 兴趣热度分、某人兴趣标签的置信度、我的社交契合度分 |
| 人-人关系图谱 | 节点 = 人，连线 = 共同爱好，用于看出小圈层 |
| 聊天内联提示 | 在聊天上下文的消息旁直接给出兴趣提示 |
| **爱好雷达图** | 五个轴 = 运动 / 艺术 / 游戏 / 娱乐 / 社交；点击任一轴展开该维度下的二级具体词条（运动 → 乒乓球、羽毛球；游戏 → 具体端游 / 手游名） |
| **性格雷达图** | 六个轴 = 领导式 / 活泼 / 幽默 / 冷静 / 理性 / 判断；闭集固定（见 §5.7） |
| **个人标签词云** | 按该成员自己的 tag 生成（与模块一的梗词云不同物，见 §2.1） |

### 5.6 新增指标：回复时长

- **回复时长**：显示某人的回复时长，用于判断「找这个人搭话要等多久」。
- 口径（CHG-013 定稿）：以「被 @ 或直接接话」为触发，统计**首条回复间隔的中位数**；排除纯表情回复与跨天回复。
- **活跃度**：沿用发言量口径，与「社交」维度分数同源（§5.2），不重复计入契合度。
- 「**活跃时间 / 夜猫指数**」**不做**：来源 input 该段为误记，已排除（CHG-012）。

### 5.7 性格标签

- **六个维度（闭集固定）**：领导式 / 活泼 / 幽默 / 冷静 / 理性 / 判断。
- 产生方式：由 LLM 从群聊消息**推断**，但**必须经本人确认后才入库并展示**；未确认的候选不得出现在任何产物与视图中。
- 支持人工介入：本人可增、删、改自己的性格标签。
- 性格标签与分数**仅对使用者本人可见**，不外露给群成员（承接 §5.1）。

### 5.8 评分口径

- **兴趣热度分**：每个爱好下的人的活跃 / 投入程度。
- **兴趣置信度**：某人在这项爱好上有多可信。
- **我的社交契合度分**（原称「我的社交匹配度分」，CHG-012 改名，口径未变）：两个都要 —— ①我 vs 每个群友的逐人契合度（列表）；②我在群里的整体融入度（单一分数）。
- **雷达图维度分**（爱好五维、性格六维共用同一条规则）：该维度下所有二级标签的**置信度求和**（CHG-013 定稿）——提及越多、越可信，该维度分越高。

### 5.9 冷启动与未知成员

发言太少、不足以推断兴趣的成员，标为**"未知"，不做推测**；但仍然列出，并注记"未知"。

人-人图谱中的处理（CHG-013 裁定）：**列入图谱但零连线**（孤立节点），避免用猜测的连线污染图谱。
