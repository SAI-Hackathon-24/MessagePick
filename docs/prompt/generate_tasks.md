# 目标
基于设计声明，把 MessagePick 拆分为可独立实施、可独立验证的实施任务。

# 输入
docs/design/modules.md
docs/design/api-contract.md
docs/design/data-model.md

# 输出
docs/plan/tasks.md

# 步骤
1. 阅读并理解上述设计声明
2. 提问确认模糊的地方（提问未闭环时禁止产出）
3. 生成 docs/plan/tasks.md
   - 要求：每个任务都必须包含下列内容，缺一不可：
     - ID 与覆盖：分配 `TASK-###`（三位数字，永不复用），标注覆盖的 `MOD-###` / `API-###` / `DM-###`
     - 任务粒度：能在一次可验证的提交内完成；判断标准是「能独立验证」，不是「能独立写完」
     - 前置依赖：必须先完成哪些 `TASK-###`；无依赖须显式写「无」，不得留空
     - 完成判据：可判定的产出物（具体到哪份文档 / 哪个 `API-###` / 哪条 `AC-###` 通过），不是「写完了」
     - 规模预估：相对量级 S / M / L，不写绝对人天
   - 总览要求：
     - 任务清单表：`TASK-###` / 覆盖条目 / 前置依赖 / 完成判据 / 规模
     - 依赖顺序图（mermaid 或分阶段列表），并标注关键路径
   - 覆盖要求：每个 `MOD-###` 至少被一个 `TASK-###` 覆盖；未被覆盖的必须显式列出并提问。

# 额外要求
不指定技术栈、不写代码、不写具体命令。
不把任务写成「实现 X 模块」这种不可验证的描述。
任务是实施顺序，不是模块清单：一个 `MOD-###` 拆成几个 `TASK-###` 由可验证性决定，不要一个模块对一个任务就交差。
不要擅自做出决定。不要揣测我的意图。有任何不清楚的地方必须通过提问的方式问清楚我。尽量调用copilot内置工具向我提问。
