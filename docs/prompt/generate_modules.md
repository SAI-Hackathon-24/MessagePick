# 目标
基于 PRD，按架构模块（层/服务/组件）拆分 MessagePick，输出模块拆分声明、模块依赖与模块间接口声明。
本阶段只做「声明」，不产出具体实现。

# 输入
docs/product/prd.md

# 输出
docs/design/modules.md

# 步骤
1. 阅读并理解 prd.md
2. 提问确认设计中模糊的地方（提问未闭环时禁止产出）
3. 按架构模块拆分，并将结果输出到 docs/design/modules.md
   1. 要求：对每个模块，明确下述内容：
      模块职责与边界：负责什么、明确不负责什么。不负责的部分要写清楚，比负责的部分更有价值。
      模块间接口声明：对外暴露的接口签名（入参、出参、错误码/异常类型），只声明契约，不写实现。
      数据模型与字段：该模块持有或依赖的字段、来源、类型、默认值、约束条件。
      依赖与调用方：依赖哪些模块、被哪些模块调用，以及不允许出现的依赖方向（如反向依赖、循环依赖）。
      验收标准：可判定。能被测试写成用例，而不是"模块划分合理"这种。
   2. 总览要求：给出模块清单表格 + 模块依赖图（mermaid），并标注每条依赖的方向与用途。

# 额外要求
输出文档的每条条目必须带 `docs/README.md` §5.2 规定的 ID 前缀：每个模块分配 `MOD-###`，并标注它承接的 `REQ-###`。ID 为三位数字，一经分配永不复用；跨文档引用只写 ID，不复述正文。
只输出声明，不输出实现：不写函数体、不写伪代码、不选具体技术框架。若 PRD 未指定技术选型，必须提问而非假设。
不要擅自做出决定。不要揣测我的意图。有任何不清楚的地方必须通过提问的方式问清楚我。尽量调用copilot内置工具向我提问。
