# 目标
基于 PRD 与设计声明，把每条需求转成可执行的验收用例，形成发布前的最终检查清单。

# 输入
docs/product/prd.md
docs/design/modules.md
docs/design/api-contract.md
docs/design/data-model.md
docs/plan/tasks.md

# 输出
docs/plan/acceptance-tests.md

# 步骤
1. 阅读并理解上述文档
2. 提问确认模糊的地方（提问未闭环时禁止产出）
3. 生成 docs/plan/acceptance-tests.md
   - 要求：每条用例都必须包含下列内容，缺一不可：
     - ID 与覆盖：分配 `AC-###`（三位数字，永不复用），标注覆盖的 `REQ-###`；能定位到接口或字段时补标 `API-###` / `DM-###`
     - 前置条件：数据状态、权限、环境
     - 操作步骤：逐步可复现
     - 期望结果：可判定（具体值 / 具体状态 / 具体提示文本）
   - 覆盖率要求：
     - 每条 `REQ-###` 至少被一条 `AC-###` 覆盖
     - 必须覆盖异常分支：空状态、失败、超时、无权限
     - 必须覆盖边界与等价类：上限 / 下限 / 非法输入
   - 总览要求：
     - 用例清单表
     - 「需求 → 用例」覆盖矩阵；未被覆盖的 `REQ-###` 必须显式列出并提问原因，不得静默略过

# 额外要求
只写用例，不写测试代码、不选测试框架。
期望结果必须可判定（具体值 / 具体状态 / 具体提示），禁止「正常工作」「体验良好」。
本阶段是流水线终态：若发现 `REQ-###` 本身有缺口或自相矛盾，**回流上游**（走 design-doc-change skill），不要就地改判。
不要擅自做出决定。不要揣测我的意图。有任何不清楚的地方必须通过提问的方式问清楚我。尽量调用copilot内置工具向我提问。
