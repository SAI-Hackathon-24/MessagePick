# 目标
基于 PRD 与模块拆分声明，输出统一的数据模型声明（实体、字段、关系、约束）。本阶段只做「声明」，不产出实现。

# 输入
docs/product/prd.md
docs/design/modules.md

# 输出
docs/design/data-model.md

# 步骤
1. 阅读并理解 prd.md 与 modules.md
2. 提问确认模糊的地方（提问未闭环时禁止产出）
3. 生成 docs/design/data-model.md
   - 要求：每个实体都必须包含下列内容，缺一不可：
     - ID 与归属：分配 `DM-###`（三位数字，永不复用），标注归属模块 `MOD-###` 与来源需求 `REQ-###`
     - 字段：名称、类型、来源（用户输入 / 计算 / 外部获取）、默认值、是否可为空、约束
     - 计算口径：由其他字段派生的字段，必须写出计算公式或规则
     - 关系：实体间的基数与级联行为（创建 / 更新 / 删除时如何传导）
     - 生命周期：创建时机、可变字段、删除或归档规则
   - 总览要求：
     - 实体清单表：`DM-###` / 归属 `MOD-###` / 来源 `REQ-###` / 一句话用途
     - 实体关系图（mermaid ER）
   - 覆盖要求：modules.md 中声明「持有数据」的模块都必须有对应 `DM-###`。
     若某个模块在数据模型上没有落点，必须显式列出并提问确认，不得默认省略。

# 额外要求
只声明模型，不写实现：不写建表语句、不写 DDL、不选具体数据库、不写 ORM 映射。
字段必须有来源，无法回溯到 PRD 的字段要么删除要么提问。
若 PRD 未给出某个字段的口径或默认值，必须提问而非假设。
不要擅自做出决定。不要揣测我的意图。有任何不清楚的地方必须通过提问的方式问清楚我。尽量调用copilot内置工具向我提问。
